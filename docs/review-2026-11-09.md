# QS tile review (2026-11-09)

The connected phone reported AudioX present and enabled=false after a tile off
click, while SystemUI cached the tile as state=0 (unavailable). Thus the off
command reached the engine, but the tile could not be clicked again.

ORealityTileService previously equated a missing asynchronous service connection
with a missing engine. onStartListening()/onClick() could publish state=0 before
onServiceConnected(). CustomTile.handleClick() explicitly drops clicks in this
state. The effect owner is a persistent service in the same process; the tile
now uses that existing owner while its binding is pending, and waits without
publishing when neither reference is ready. A real missing engine still reports
unavailable. Unlocked clicks no longer wait for unlockAndRun's SystemUI/keyguard
round trip; locked clicks still wait for unlock.

`python3 tools/tests/test_tile.py` tests the real tile implementation with deferred
binding, queued clicks, warm on/off toggles before the bind callback, stopped
listening cleanup, actual missing engines and keyguard deferral. The original
implementation fails the first regression. verify-port.py includes this check.
The complete app compiles against Android 17 system-server SDK stubs and its
resources link against the phone's Android 17 framework-res.apk. No APK was
installed: corrected runtime UI behavior must still be verified on the device.

# Engine volume mapping

Both the source product configuration and the running phone use 30 media volume
steps. The vendor engine accepts indices 0..16 (stock AudioEffectCenter d0.h.n).
The previous raw clamp sent index 16 for every UI value from 16 through 30,
selecting the maximum-volume tuning throughout almost half the slider.

EffectProtocol now maps larger ranges to 0..16 while preserving native 15/16-step
indices. Both AudioX and Holo consume this shared value, including AudioX EQ's
volume-specific payload. Examples: 15/30 -> 8, 24/30 -> 13, 30/30 -> 16.
Host regressions cover these, stock's 160-step range, native ranges and invalid
inputs. This changes tuning selection, not the system stream's actual volume.
Audible behavior across the volume slider remains to be verified on the phone.
